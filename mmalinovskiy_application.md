**[ НАЗВАНИЕ ПРОЕКТА ]**

«ОлимпРадар — персональный советник школьника по олимпиадам»

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Ежегодно в Перечень олимпиад РСОШ входит около 80 олимпиад и их площадок: сотни этапов с разными датами регистрации, форматами и уровнями льгот в вузах. Школьник 8–11 класса, выбирающий, куда вложить силы в этом сезоне, сталкивается с информацией, разорванной по десяткам сайтов: календари на порталах организаторов, карты льгот на сайтах приёмных комиссий, опыт участников — в чатах и на форумах. Из-за этого школьники массово пропускают регистрации, не знают, что уже имеют право на БВИ или 100 баллов по имеющемуся диплому, и выбирают олимпиады не под свой профиль, а «по слухам».

К сервисам для подготовки к олимпиадам предъявляются следующие требования: 1) актуальные данные по этапам и дедлайнам сезона, 2) персонализация под класс, предметы и цель поступления, 3) объяснимость рекомендаций, 4) безопасность сообщества несовершеннолетних. Однако во всех имеющихся программных продуктах **отсутствует**, по нашим данным: 1) объяснимый персональный скоринг «почему именно тебе» с разбором по компонентам и подсказками «как поднять балл»; 2) единый таймлайн дедлайнов с обнаружением конфликтов этапов и экспортом в календарь (.ics); 3) связка «олимпиада → конкретная льгота → цель поступления» со стратегией и дорожной картой по классам; 4) модерируемое сообщество (чаты, отзывы, личные сообщения), построенное с учётом того, что аудитория — несовершеннолетние: без сбора ФИО, телефонов и геолокации. Заявляемый программный продукт решает эти проблемы: рекомендательное ядро с прозрачной формулой, радар дедлайнов сезона, конструктор стратегии поступления через льготы и безопасное сообщество с модерацией.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

Продукт рассчитан на школьников России, участвующих в олимпиадном движении, однако выделяются несколько групп пользователей со своими сценариями:

- Учащиеся 8–9 классов — ранняя навигация: с какими олимпиадами стоит познакомиться до профильного возраста, как строится «дорожная карта» классов;
- Учащиеся 10–11 классов — плотный сезон: подбор под профиль и цель поступления, таймлайн дедлайнов, карта льгот БВИ / 100 баллов / доп. баллов;
- Учащиеся с уже полученными дипломами — проверка, какие цели поступления их дипломы уже «закрывают», и что добирать;
- Родители и наставники/учителя — обзор сезона, стратегии и достижений ученика (print-friendly страница «Мои достижения» с экспортом в PDF);
- Модераторы и администраторы сервиса — внутренняя аудитория: очередь модерации, CRUD справочников, аналитика и дайджесты.

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

Продукт реализуется как веб-приложение (сознательно одна платформа — все усилия направлены на функционал). К моменту сдачи существует в виде версии для следующих конфигураций:

- Любая современная ОС с браузером: Chrome / Firefox / Edge / Safari актуальных версий;
- Серверная часть: Node.js 20+ (рекомендуется 22/24 LTS), 512 Мб оперативной памяти, 200 Мб дискового пространства; ОС — Windows 10+/Linux/macOS;
- База данных: SQLite (файл `prisma/dev.db`); схема совместима с PostgreSQL — миграция сводится к смене `provider` и `DATABASE_URL`;
- Клиентская часть: без внешних запросов (CSP `default-src 'self'`), работает в локальной сети и на VPS.

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Программный продукт предоставляет следующие возможности:

- Мастер профиля (онбординг): класс, регион, предметы, уровень, цель поступления → сразу топ-3 рекомендаций с живым скорингом;
- Объяснимый скоринг «Почему тебе»: формула `Score = 30·S + 20·L + 25·B + 15·T + 10·I` (предметы, класс, льготы, время, интересы) с разбором каждого компонента и блоком «Как поднять балл» (контрфактивная симуляция);
- Каталог олимпиад: фильтры в URL (шарящиеся ссылки), быстрый поиск с подсказками, сортировка по персональному скорингу, сравнение до 3 олимпиад;
- Карточка олимпиады: этапы сезона, «Почему тебе», карта льгот по вузам, отзывы с ответами, чат, похожие олимпиады;
- Таймлайн-радар дедлайнов: лента сезона, обнаружение конфликтов этапов, «загрузка сезона» одной кнопкой, экспорт в .ics;
- Стратегия поступления: цели (вуз/программа), карта льгот БВИ / 100 баллов / доп. баллов, дорожная карта по классам;
- Личный план: подписки на олимпиады, трекер дипломов, автоматическое закрытие целей поступления дипломами, страница «Мои достижения» (печать в PDF);
- Уведомления: дедлайны (с дедупликацией «один дедлайн — одно уведомление»), ответы на отзывы, статусы модерации; еженедельный email-дайджест (имитация отправки по ТЗ);
- Сообщество: чаты по олимпиадам, отзывы с премодерацией, личные сообщения (только из чатов, «из воздуха» нельзя), жалобы, скрытие сообщений, журнал модерации;
- Безопасность несовершеннолетних: без ФИО/телефонов/геолокации, фильтры чатов (запрет ссылок, маскировка контактов), rate limiting, JWT-сессии в httpOnly-cookie, CSRF-барьеры, экспорт «Мои данные» одним JSON;
- Роли: пользователь / модератор / администратор; админ-панель с аналитикой (EventLog), очередью модерации, CRUD олимпиад/этапов/льгот/предметов, управлением пользователями и дайджестами;
- Интерактивная экскурсия по интерфейсу для новых пользователей.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

Анализ 3 программных продуктов, максимально приближенных к заданному функционалу, показал, что:

- Olimpiada.ru (МЦНМО/ВШЭ): ведёт календарь и новости олимпиад, но не персонализирует выдачу — нет профиля ученика, скоринга и объяснений «почему тебе»; карта льгот не связана с целями поступления;
- Перечень РСОШ (rsr-olymp.ru): официальный реестр олимпиад и организаторов — источник данных, а не советник: нет этапов в календарном виде, напоминаний, рекомендаций и сообщества;
- Каталоги профориентации («Учёба.ру» и аналогичные): описания олимпиад в формате статей, без учёта класса/предметов, без таймлайна дедлайнов, трекера дипломов и стратегии поступления через льготы.

Ни один из аналогов не совмещает объяснимое рекомендательное ядро, радар дедлайнов с конфликтами, конструктор стратегии поступления и модерируемое сообщество с защитой несовершеннолетних.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]**

- Next.js 16 (App Router) + React 19 + TypeScript (strict) — веб-платформа, серверный рендер и API route handlers;
- Tailwind CSS 4 — дизайн-система (собственные ui-компоненты в структуре shadcn без transitive-зависимостей);
- Prisma 6 — ORM и миграции;
- SQLite — файловая СУБД; схема (≈20 моделей: User, Profile, Olympiad, Stage, Benefit, Subject, Subscription, Diploma, UserTarget, Review, ChatMessage, DirectMessage, Report, ModerationLog, Notification, EmailDigest, EventLog, ScanState и др.) сознательно совместима с PostgreSQL: перечисления — `String` с контролем значений через zod, списки — JSON-колонки; на PostgreSQL поднимается без изменения схемы;
- zod — валидация всех входных данных на сервере (сообщения об ошибках на русском);
- jose (JWT HS256) + bcryptjs — собственная сессионная система: httpOnly-cookie, ротация токена, роли на сервере;
- ESLint 9 — качество кода (сборка и линт проходят без ошибок и предупреждений).

**[ ВОЗМОЖНЫЕ РИСКИ ]**

- Актуальность данных: даты этапов и условия льгот меняются каждый сезон — необходима регулярная сверка с официальными источниками (в карточке хранятся ссылка на источник и дата обновления);
- Модерация сообщества несовершеннолетних: нагрузка на очереди модерации, риск обхода фильтров чатов — требует развития инструментов (автофлаги, расширение журнала);
- Точность карты льгот: условия вузов различаются по программам и годам действия — ошибка в справочнике вводит пользователя в заблуждение;
- Технические ограничения демо-версии: rate limiter в памяти процесса (для кластера нужен общий store), реальная отправка email отключена по ТЗ;
- Неправильная оценка стека и объёма функций в одиночной разработке, как следствие — нехватка времени на доведение второстепенных модулей.
